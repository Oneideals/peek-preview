一篇用来验证阅读视图的文章

作者：Peek 测试

阅读视图会把网页里无关的导航、广告和侧栏都去掉，只留下正文重新排版。为了通过正文抽取的阈值，这篇文章需要足够多的文字。下面几段会反复说明一些看起来很像文章的内容，实际上它们只是测试数据。

第一段用来描述背景：很多时候我们打开一个链接，只是想快速确认它是不是自己要找的那一篇。传统做法是新开一个标签页，看完再关掉，标签栏很快就挤满了。悬浮预览把这一步压缩成一次点击，看完按 Esc 就能回到原来的阅读位置。

代码与表格的样式

阅读视图会保留正文里的代码块和表格，并给它们加上适合窄浮层的样式。代码块可以横向滚动，表格也不会把浮层撑破。下面是一个简短的示例：

function greet(name) {
  return 'hello, ' + name;
}
console.log(greet('peek'));

表格同样需要能横向滚动，尤其是列数较多的时候。下面这张表有三列，用来检查表头和单元格的边框是否正常：

功能入口说明
悬浮预览Shift + 点击在当前页面上浮出内容
阅读视图Alt + R抽取正文并重新排版
沉浸模式标题栏按钮浮层铺满整个屏幕

脚注在正文里通常是一个上标数字1，阅读视图也应该保留这种上下标关系。下面还有一段文字，用来确保正文长度超过抽取阈值，不会被判定成非文章页。

最后一段做一个收尾：如果你能在浮层里看到这句话，说明正文抽取、HTML 清洗和 srcdoc 渲染这条链路都是通的。链接导航也会被拦截并通过 postMessage 交回外层处理，不会把阅读视图本身导航掉。
